# SuperSLM 1.14.0

Released 2026-10-23.

SuperSLM 1.14.0 adds frozen-prefix save and restore on the CPU. A host can build a shared prompt prefix once (a
world, a persona), save it as a canonical `SPX1` blob, and later restore it instead of prefilling it again. A
restored prefix is adopted exactly as the prefill-built one is, and its adopters emit the same tokens. A nested
prefix can be restored onto its parent and share the parent's pages. The blob records the engine version that
wrote it, and a blob from another version is refused with a new status, `SSLM_RESTORE_PRODUCER_MISMATCH`
(ordinal 30).

One existing behavior changes: model mapping now refuses a model whose schema names include two with the same
FNV-1a 64-bit hash, or one whose name hashes to zero, on both backends. A caller mapping such a model gets
`SSLM_ARTIFACT_REJECTED` from `sslm_model_map` (`SSLM_DEVICE_LOST` from `sslm_gpu_model_map`) and no model handle,
where 1.13.1 mapped it; re-converting it with distinct schema names fixes it. The certified model artifacts still map.
No token, existing status or sequence save format changes.

## What changed

- **`sslm_prefix_save(prefix, buf, &n)`** writes a frozen prefix as `SPX1` bytes. It uses the two-call buffer
  convention: a null or short buffer returns `SSLM_BUFFER_TOO_SMALL` with the exact size in `*n`. An unfrozen
  prefix is `SSLM_INVALID_ARGUMENT`. Saves of one frozen prefix may run concurrently.
- **`sslm_prefix_restore(model, pool, buf, n, parent_or_null, &out, &shared)`** validates the whole blob before
  it draws or shares any page: size and magic, the SHA-256 digest, backend, producer, model identity, KV
  precision, schema binding and every field's domain. A nested blob (origin above 0) shares the hint's leading
  `floor(origin / B)` pages when the hint is a frozen prefix of the same model and pool, holding exactly the
  blob's origin, with byte-equal rows over those pages; it then draws `ceil(length / B) - floor(origin / B)`
  pages. Any other hint restores the same prefix privately. Every refusal clears `*out` and returns every page
  drawn.
- **`SPX1`** carries the CPU backend, the producer version, the model hash, KV precision, the schema binding and
  walk state, the current token, length and origin, the hidden scale, five saturation counts, the residual and the
  canonical K/V rows. Its exact size is `184 + hidden_size + length * bytes_per_token`. It omits page identities
  and page size, so a blob restores into a pool of any page size. The digest detects accidental change; it does
  not authenticate the bytes. `docs/api.md` states what an edited blob with a recomputed digest can choose.
- **New status `SSLM_RESTORE_PRODUCER_MISMATCH` (ordinal 30)**, appended at the end of `SSLM_STATUS_ENUM_LIST`:
  every published ordinal is unchanged.
- **`SSLM_HAS_PREFIX_SAVE_ABI`** is defined to 1 in `sslm_abi.h`, so a host can test for the two verbs and the new
  status at compile time.
- **`include/superslm/sslm_version.h`** (new) carries `SUPERSLM_VERSION_MAJOR`, `_MINOR` and `_PATCH`. A check
  keeps it equal to CMake's project version, and the blob's producer field is this version.
- **Model mapping refuses colliding schema name hashes.** A model whose schema names include two with the same
  nonzero FNV-1a 64-bit hash, or one hashing to zero, is refused at map on both backends. A saved schema hash
  then resolves to exactly one schema. The certified model artifacts still map.
- **MSVC GEMM placement pin.** `src/matmul.cpp` gets its own image section, so the GEMM kernels' alignment no
  longer moves with unrelated edits. `tools/msvc_pin/run-pinmap.ps1` checks the placement.

## Exported but not released: the GPU twins

The GPU save and restore verbs are declared in `gpu_1p0.h` and exported by the GPU library, but they are
unreleased until 1.16.0, and no release before 1.16.0 promises their behaviour:

- `sslm_gpu_prefix_save` (unreleased until 1.16.0);
- `sslm_gpu_prefix_restore` (unreleased until 1.16.0), and the status-30 refusal it returns.

A host should not depend on them yet. Their documentation in `docs/api.md` carries the same label.

## Compatibility and required action

- The CPU ABI change is additive: two verbs, one status appended at 30, one macro and one header. No existing
  declaration, struct layout or status ordinal changes.
- **A blob is bound to the engine version that wrote it.** A host that caches blobs across an engine upgrade
  gets `SSLM_RESTORE_PRODUCER_MISMATCH` and must rebuild the prefix by prefill. Key a cache by engine version.
- Sequence saves are unchanged: `SSB5`, `SSB6` and the GPU's `SLM5` and `SLM6` saves written by 1.13.1 restore
  on 1.14.0 (cells 9.9 and 9.10).
- A model with two schema names colliding in FNV-1a 64, or a name hashing to zero, no longer maps. Re-convert it
  with distinct names.
- No model artifact needs reconversion, and the shaders are unchanged.

## Verification

The test results are summarized in [`1.14.0-verification.md`](1.14.0-verification.md). It covers timings, the
cross-compiler byte equality, the Windows and long runs, ThreadSanitizer, the release-tree checks, the reference
streams and the reviews.

Most Windows records were taken on trees whose engine source equals the release's apart from the version header
(`sslm_version.h`). The Windows version checks therefore read 1.13.1. 1.14.0's version checks, the full CPU suite at
the release commit and the 9.5 pins ran on Linux with GCC. 9.10 is green on both certified GPUs, the NVIDIA GeForce
RTX 2080 SUPER and the AMD Radeon RX 7900 XTX. The first CI run on `main` follows the merge.
