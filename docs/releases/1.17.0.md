# SuperSLM 1.17.0

Released 2026-10-26.

SuperSLM 1.17.0 brings schema skip-ahead to the GPU, and fixes wrong GPU results on NVIDIA RTX 50-series cards.

Under a bound schema, the GPU can now score only the tokens the schema allows at each step (the masked finish), and
can write the text a schema forces in one pass instead of one token at a time (jump-forward, canonical mode). These
are the GPU twins of 1.15.0's CPU verbs. Nothing changes unless a host calls the new verbs; no save format (`SLM5`,
`SLM6`, `SPX1`) changes, and no model artifact needs reconversion.

## Fixed: wrong GPU results on NVIDIA RTX 50-series (Blackwell)

On RTX 50-series cards the driver's shader compiler drops the carry from the low 32 bits into the high 32 bits of a
native 64-bit integer add in some kernels. One such add derives the softmax's scale constants, so every GPU forward
went wrong at the first attention layer: the open-time check refused the device, and 59 checks of the GPU suite
failed (1.16.0's known issue). The add is now formed from two 32-bit halves with an explicit carry, which gives the
same result as the native add wherever that add is computed correctly. The shader compiler keeps that form at full
optimisation on every dxc version checked (Windows SDK 10.0.22621 and 10.0.26100, and three Linux builds).

On an RTX 5060 the full suite now passes, CPU and GPU: 326,327 checks, 0 failures. Results on other cards are
unchanged.

## What's new

- **`sslm_gpu_seq_forced_tokens(ctx, seq, out_ids, cap, out_count, out_accepting)`** returns the text the bound schema
  forces from the sequence's walk state, as token ids, the same ids the CPU's `sslm_seq_forced_tokens` returns. A
  model mapped without a forced-next table (an artifact with no tokenizer section) returns the new
  `SSLM_GPU_FORCED_TABLE_ABSENT` (ordinal 31).
- **The GPU masked finish.** Under a bound schema the decode bridge's last step scores only the legal rows, when the
  head rows are on the host or tied to the embedding. Tokens are unchanged. Models whose device head is untied from
  the embedding keep the full finish in 1.17.0. On a tied device-head model a host parallel-for hook that does not
  run every task now makes the finish return `SSLM_GPU_PARALLEL_FOR_INCOMPLETE`, so a retry finishes the same row.
- **`sslm_gpu_seq_jump_forward(...)`** admits the pending token and the chain the schema forces, at most
  `chunk_budget` rows in one call, with `sslm_gpu_seq_embed_schema_token` and `sslm_gpu_seq_ready_for_logits`. A call
  that would pass the context cap admits the rows that fit and returns the new `SSLM_GPU_CONTEXT_CAP_EXCEEDED`
  (ordinal 32). A failure inside the pass restores the entry state. The GPU verb refuses `SSLM_JUMP_EXACT` in 1.17.0:
  exact mode on the GPU needs multi-row dispatch, which 1.18.0 brings.
- The two new status names are appended to the CPU's status list too, so the CPU and GPU enums keep one ordinal
  space. No CPU call returns either.

See [docs/api.md](../api.md#schema-skip-ahead-on-the-gpu-1170) for the full contract.

## Canonical mode changes answers, and is deprecated

Canonical jump-forward writes the forced text with the tokenizer's own split instead of the model's, and the model
then continues from tokens it would not have chosen. On a user's schema-heavy workload of 44 lines on the CPU
(1.16.0), exact mode took 0.46 s a line with all 44 answers identical to skip-ahead off (0.63 s), while canonical took
0.44 s but changed 8 of the 44 answers and lowered accuracy. On array schemas (convertible from 1.19.0) canonical
closes an array after its first item. **1.18.0 removes canonical mode on the CPU and the GPU.** Use exact mode on
the CPU where answers matter (pass `SSLM_JUMP_EXACT`; NULL options select canonical). On the GPU, 1.17.0 offers
canonical only.

## Tested on

- **NVIDIA GeForce RTX 5060** (driver 32.0.16.2101): the full suite, CPU and GPU, 326,327 checks, 0 failures; and GPU streams equal the CPU's token for token on
  41 schema-bound prompts with skip-ahead off and in canonical mode at 1, 2 and 4 rows per call, with the head on
  the device and on the host.
- **AMD Radeon RX 7900 XT** (driver 32.0.21030.2001): the same 41-prompt stream check, every arm equal to the CPU.
  Its streams are byte-identical to the RTX 5060's. The skip-ahead verb's own GPU cells (smoke plus 18 cells: entry shapes, partial
  admission at the context cap and the K/V budget, save and restore between calls, and the rest) pass on it with the
  D3D12 debug layer on and no debug-layer messages.
- Stream equality is claimed only on these cards. No GPU determinism is claimed for any other GPU.
