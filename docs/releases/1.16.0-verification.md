# SuperSLM 1.16.0: test results

This page summarizes the testing behind 1.16.0's GPU frozen-prefix save and restore (`sslm_gpu_prefix_save`,
`sslm_gpu_prefix_restore`, the `SPX1` blob with backend 1). It is written for developers deciding whether to use the
feature. The release note, [`1.16.0.md`](1.16.0.md), describes the API. The raw logs and per-run records are kept on
the development branch, not here.

Test cells are named the way the test sources name them. Each source file lists its cells in its header.

## In short

- Three GPUs were tested: the NVIDIA GeForce RTX 2080 SUPER, the AMD Radeon RX 7900 XTX and the AMD Radeon RX 7900 XT.
  The first round (the save and restore cells, with the D3D12 debug layer and GPU-based validation on) ran on the
  RTX 2080 SUPER and the RX 7900 XTX. The second round (the real 0.5B and 1.5B models, byte identity and speed) ran on
  the RTX 2080 SUPER and the RX 7900 XT. Every cell is green on every card it ran on.
- A prefix built by prefill on the CPU, on the RTX 2080 SUPER and on the RX 7900 XT gives byte-identical `SPX1` rows
  for 1,000 tokens of the real 1.5B and 0.5B models.
- Restoring a saved prefix instead of prefilling it is at least 510 times faster at 128 tokens and at least 1,100
  times faster at 1,000 tokens, on both cards timed (lower ends of 95% intervals).
- A blob saved on one card is refused on another with `SSLM_RESTORE_PRODUCER_MISMATCH`, in both directions, and a blob
  restores on the card that wrote it. This release keeps that refusal, although the bytes were measured identical.
- The first round ran on the 1.15.0 tree, whose engine source equals 1.16.0's apart from the version number and the
  lifted labels. The second round ran on the 1.16.0 tree.

## Round one: the GPU save and restore cells (RTX 2080 SUPER, RX 7900 XTX)

Both GPUs ran the same executables, built with MSVC 14.34 and Windows SDK 10.0.22621.0 from the `main` tree after
1.15.0 (engine version 1.15.0), on two Windows machines. Each piece ran alone, with no other GPU work on the machine.

| Piece | What it covers | RTX 2080 SUPER | RX 7900 XTX |
|---|---|---|---|
| GPU save/restore cells, debug layer on | the blob format, the pool and nested sharing, Busy, injected faults, the budget-stop snapshot, the derived ready and bind state (six cells) | 810 checks, 0 failures | 810 checks, 0 failures |
| Schema name hashes at GPU model map, debug layer on | the GPU map refuses a model with two colliding schema name hashes or a zero hash, and maps the renamed pair | 8 / 0 | 8 / 0 |
| Paged-KV GPU cells, step G5, debug layer on | 24 cells | 1,074 / 0, 0 skipped | 1,074 / 0, 0 skipped |
| Paged-KV GPU cells, step G4 except 1.9, debug layer on | 17 cells | 1,418 / 0, 0 skipped | 1,418 / 0, 0 skipped |
| Paged-KV GPU cell 1.9, debug layer off | the long randomized pool cell (135 creates, 279 adopts, 47 prefills, 118 resets, 125 releases, 118 prefix rebuilds) | 4,125 / 0 | 4,125 / 0 |

- The six save/restore cells are 258, 266, 23, 135, 75 and 53 checks on each card.
- In the paged-KV cells that count them, the debug layer reported no message at WARNING or above, on either card. The allocation failures the
  fault cell injects are expected, and the cell checks each one's refusal.
- Cell 1.9 runs with the debug layer off. Under GPU-based validation it takes about 90 minutes on the RTX 2080
  SUPER, and it ran alone so as to stay in bounded time.

## Different card, refused

- The RTX 2080 SUPER saved a 15,736-byte blob (producer vendor `10de`, device `1e81`) and restored it on itself: 14
  checks, 0 failures.
- The RX 7900 XTX refused that blob as another card's, with a null out-handle, then saved its own (vendor `1002`,
  device `744c`, 15,736 bytes) and restored it on itself: 14 checks, 0 failures.
- The RTX 2080 SUPER refused the RX 7900 XTX's blob with `SSLM_RESTORE_PRODUCER_MISMATCH` and a null out-handle: 8
  checks, 0 failures.

## The test catches a broken build

The Busy cell was rebuilt against a deliberately broken library, with the submission guard removed from the GPU
restore. On the RTX 2080 SUPER it went red (21 checks, 3 failures), naming the Busy rule, so the cell can tell a
restore that ignores in-flight work from a correct one.

## Round two: real models, byte identity and speed (RTX 2080 SUPER, RX 7900 XT)

Both cards ran the same executables, built with MSVC on the RTX 2080 SUPER's machine from the 1.16.0 tree plus the
test cells. Two test-only hooks are compiled into the test builds alone, never into the shipped library, and the
timing cell refuses to build with them. The D3D12 debug layer was off for this round. Each step ran alone, after a
rest, and the timing steps checked, before and after each length, that no other test, build or editor was running, and
on the RX 7900 XT also no browser, video or chat program.

The RX 7900 XT reports PCI device ID `744c`, the same ID as the RX 7900 XTX. The engine cannot tell the two cards
apart, so by construction each accepts the other's blobs. That was not tested, and byte identity was not measured on
the RX 7900 XTX.

|---|---|---|---|
| Save/restore cells, schema cell, 1.13.1 GPU saves (`9_10`) and cell 6.5 on the synthetic models | the first round's cells again on the 1.16.0 tree, and the 1.13.1 sequence saves | 1,852 checks, 0 failures | 1,852 / 0 |
| Byte identity, cell 4.6, 1.5B and 0.5B at 1,000 tokens | the CPU and the GPU build the same prefix and save it | 23 + 23 checks, 0 failures; 41 + 41 / 0 in the cross-check | 41 + 41 / 0 |
| Cell 6.5, 1.5B and 0.5B | prefixes of many lengths: rows, state, round trip, and 64 tokens decoded by each adopter of a restored prefix equal the prefill-built prefix's | 337 + 337 / 0 | 337 + 337 / 0 |
| Cells 10.1 and 10.2 on the GPU, real 0.5B | ten prefixes of 159 to 2,000 tokens saved, the process exits, a new process restores them, and every adopter's stream equals the prefill-built reference; no prefix prefill runs in the new process. Then the nested shape: a 1,012-token world and ten personas restored onto it, sharing its pages | 705 checks, 0 failures | 705 / 0 |
| Speed, cell 10.4 | below | met | met |

### Byte identity (cell 4.6)

At 1,000 tokens, the 1.5B model's K/V rows (112,000 rows of 128 bytes) and the 0.5B model's (96,000 rows of 64
bytes) are
byte-identical between the CPU and the RTX 2080 SUPER, and between the two GPUs. So are the residual and the
header's state fields. The whole blob is identical apart from the header fields that name the producer and the
digest that covers them (backend, engine version, adapter IDs). The CPU blobs built on the two machines have the same
SHA-256.

A blob from the RX 7900 XT was also restored on the RTX 2080 SUPER through a test-only hook that skips the adapter
check. The 64 tokens its adopter decoded equal those of the prefix the RTX 2080 SUPER built itself, for both models.

### Speed (cell 10.4)

The 1.5B model on both cards, and the 0.5B model on the RTX 2080 SUPER, each timed over one warm-up and 8 pairs of
prefill and restore. The ratio is prefill time over restore time, with its 95% interval. The restore time includes
parsing a blob already in memory, checking its digest, uploading its pages to the GPU and waiting for the upload to
finish. Reading the blob from storage (1.8 MB at 128 tokens and 14.3 MB at 1,000 for the 1.5B model) is not timed.

| Card | Model | Tokens | Prefill | Restore | Ratio, 95% interval |
|---|---|---|---|---|---|
| RTX 2080 SUPER | 1.5B | 128 | 1,866 ms | 2.25 ms | 792–870× |
| RTX 2080 SUPER | 1.5B | 1,000 | 17,785 ms | 15.7 ms | 1,106–1,155× |
| RTX 2080 SUPER | 0.5B | 128 | 1,046 ms | 1.37 ms | 691–856× |
| RTX 2080 SUPER | 0.5B | 1,000 | 10,530 ms | 6.44 ms | 1,609–1,664× |
| RX 7900 XT | 1.5B | 128 | 1,704 ms | 3.03 ms | 510–628× |
| RX 7900 XT | 1.5B | 1,000 | 20,321 ms | 13.5 ms | 1,498–1,522× |

The bar was a lower end of at least 100×. Before these readings counted, the instrument was checked by a reviewer
independent of its author: the same measurement on a deliberately broken build, whose restore runs a full prefill,
read 1.0× on every row, as it must. These times are for a single sequence with nothing else on the GPU.

## Known issue

- RTX 50-series (Blackwell) GPUs fail parts of the GPU test suite; under investigation; use the CPU backend there. These results are from the three cards above
  only, and claim nothing for any other GPU.

## Not covered by this page

- **Other GPUs.** Nothing here applies to any GPU other than the three named.
- **Restoring a blob on another card or backend.** The bytes were measured identical, but this release still refuses
  a GPU blob on any card but the one that wrote it, and refuses CPU and GPU blobs on each other's backend.
- **Round two with the debug layer on.** The real-model, byte-identity and speed steps ran with the D3D12 debug
  layer off; the first round's cells ran with it on.
