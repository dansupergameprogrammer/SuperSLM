# SuperSLM 1.7.1

Released 2026-09-23.

SuperSLM 1.7.1 is a single fix: the engine library writes nothing to stdout. No token, ABI
surface, or measured figure changes from 1.7.0.

## What changed

**The engine library writes nothing to stdout.** 1.7.0 wrote `# adapter: <name>` to stdout
whenever `SSLM_GPU_ADAPTER_INDEX` was set, so a certification run could confirm which GPU actually
ran (T-2116, `tools/t2116_crossvendor/run_crossvendor.ps1`). The write came from one call site,
`Device::Init()` in `src/gpu/d3d12_harness.h`, reached twice per GPU context under that setting:
once through `harness::GetDevice()`'s process-wide singleton, and once through each
`SslmGpuContext::device`. A host that writes its own data to stdout had that line spliced into it
-- `semb query --device gpu`'s own output was corrupted this way (TE-393, D-SLM7752). The line now
goes to `stderr`, the channel every other diagnostic in the same file already uses (the
`SSLM_GPU_ENABLE_DEBUG_LAYER` messages, the D3D12 validation callback, the HRESULT-failure macro).
The information is unchanged, and `run_crossvendor.ps1` already captures the merged
stdout+stderr stream (`2>&1 | Out-String`) it reads the label from, so no script changes were
needed to keep reading it.

**Sweep.** Every stdout write reachable from the shipped `superslm` and `superslm_gpu` libraries
in `src/` and `include/` was enumerated before any fix (`printf`, `wprintf`, `puts`, `std::cout`,
`fwrite`/`fprintf` to `stdout`, and equivalents). The one call site above was the only one found;
every other library call already wrote to `stderr` or wrote nothing. Tools and tests still print
to stdout freely -- this release constrains only the shipped libraries.

## Compatibility and required action

None. `GpuContextConfig`, `GpuResidencyConfig`, every C ABI verb, and every `SslmGpuStatus`
ordinal are unchanged from 1.7.0. GPU sequence saves are unchanged (`SLM5`), and no
model-artifact reconversion is required. No arithmetic on the compute path changed: the fix
touches only a diagnostic print statement, gated the same way it always was (only when
`SSLM_GPU_ADAPTER_INDEX` is set), on `Device::Init()`'s existing early-return structure. Any host
that was reading the `# adapter:` line from stdout must read it from stderr instead; a host that
merges the two streams (as `run_crossvendor.ps1` already does) needs no change.

## Files changed

- `src/gpu/d3d12_harness.h` -- the one stdout write (`Device::Init()`) moved to stderr.
- `CMakeLists.txt`, `README.md`, `CHANGELOG.md`, `tests/install-consumer/CMakeLists.txt` -- release
  bookkeeping for 1.7.1.
