# SuperSLM 1.16.0

Released 2026-10-25.

SuperSLM 1.16.0 brings frozen-prefix save and restore to the GPU. A host can build a shared prompt prefix once on
the GPU (a world, a persona), save it as an `SPX1` blob, and later restore it into a GPU page pool instead of
prefilling it again. A restored prefix is adopted as the prefill-built one is. A nested prefix can be restored onto
its live parent and share the parent's pages. This is the GPU twin of 1.14.0's CPU save and restore, and it uses
the same `SPX1` format with backend 1.

The two verbs have been declared in `gpu_1p0.h` and exported since 1.14.0, labelled unreleased until 1.16.0. This
release lifts the label. Their code, declarations and `SslmGpuStatus` ordinals are unchanged from 1.15.0.

## What changed

- **`sslm_gpu_prefix_save(ctx, prefix, blob, &size)`** writes a frozen GPU prefix as `SPX1` bytes: its rows
  `[0, L)` gathered from the pool's host mirror in canonical layout, the residual, scale, saturation counts, the last
  prefilled token, the schema binding as the schema's name hash, walk state and origin, the engine version and the
  context's adapter vendor and device IDs, then the SHA-256 digest. It uses the two-call buffer convention: a null or
  short buffer returns `SSLM_OUTPUT_BUFFER_TOO_SMALL` with the exact size in `*size`. A prefix that is not frozen, or
  not at rest after a whole token, is `SSLM_GPU_PREFIX_REJECTED`, and `SSLM_DEVICE_LOST` if the adapter's IDs can no
  longer be read. It submits no GPU work and is never refused Busy.
- **`sslm_gpu_prefix_restore(ctx, model, pool, blob, size, parent_or_null, &prefix, &shared)`** validates the whole
  blob before it draws or shares any page. The first failing check decides:
  1. arguments (`SSLM_SEQUENCE_KV_BUFFER_MISMATCH`);
  2. `SSLM_BUSY` while any GPU work in the process is submitted or not yet observed, and `SSLM_DEVICE_LOST` if a
     submission was stranded;
  3. size and magic, digest and backend (`SSLM_SEQUENCE_KV_BUFFER_MISMATCH`);
  4. producer: the engine version, and the adapter's vendor and device (`SSLM_RESTORE_PRODUCER_MISMATCH`, or
     `SSLM_DEVICE_LOST` if the adapter's IDs cannot be read);
  5. model (`SSLM_RESTORE_MODEL_MISMATCH`);
  6. KV precision, schema and field domains (`SSLM_SEQUENCE_KV_BUFFER_MISMATCH`);
  7. free pages (`SSLM_GPU_KV_POOL_EXHAUSTED`, nothing drawn), then the draw itself (`SSLM_GPU_ALLOCATION_FAILED`,
     `SSLM_DEVICE_LOST`) and the share of the hint's pages (`SSLM_SEQUENCE_KV_BUFFER_MISMATCH`);
  8. the device statuses of the upload (`SSLM_GPU_ALLOCATION_FAILED`, `SSLM_DEVICE_LOST`).

  It then draws `ceil(L / B) - s` pages and uploads only those. When the hint is a frozen prefix of the same model
  and pool, holding exactly the blob's origin with equal host-mirror rows, its `s = floor(origin / B)` leading pages
  are shared; any other hint gives a private restore (`s = 0`). Every refusal leaves `*prefix` null and returns every
  page drawn; a refusal other than `SSLM_DEVICE_LOST` changes nothing else.
- **`SSLM_RESTORE_PRODUCER_MISMATCH` on the GPU.** The GPU status that refuses another engine version's or another
  adapter's blob, appended last in `SslmGpuStatus` since 1.14.0, is now released with the verbs.

## A GPU blob restores only where it was written

A GPU blob restores only on the exact engine version and a GPU with the same PCI vendor and device ID as the one that
wrote it. A blob saved on one GPU model is refused on any other with a different ID, even of the same vendor, and the
host rebuilds the prefix by prefill there. The RX 7900 XT and RX 7900 XTX both report `1002:744c`, so each accepts the
other's blobs; that pairing was not tested. The GPUs it was tested on are the NVIDIA GeForce RTX 2080 SUPER, the AMD
Radeon RX 7900 XTX and the AMD Radeon RX 7900 XT, and no other; this release claims nothing for any other GPU (see the
known issue below). CPU and GPU blobs are not interchangeable: each backend refuses the other's.

The refusal is a precaution. On the RTX 2080 SUPER and the RX 7900 XT, a 1,000-token prefix of the real 0.5B and
1.5B models built on the CPU and on each GPU gave byte-identical rows (byte identity was not measured on the RX 7900
XTX).

## Measured

Restoring a saved prefix instead of prefilling it, for a single sequence with nothing else on the GPU (8 timed
pairs each):

| GPU | Model | Prompt tokens | Prefill | Restore |
|---|---|---|---|---|
| RTX 2080 SUPER | Qwen2.5-1.5B | 128 | 1,866 ms | 2.3 ms |
| RTX 2080 SUPER | Qwen2.5-1.5B | 1,000 | 17,785 ms | 15.7 ms |
| RTX 2080 SUPER | Qwen2.5-0.5B | 128 | 1,046 ms | 1.4 ms |
| RTX 2080 SUPER | Qwen2.5-0.5B | 1,000 | 10,530 ms | 6.4 ms |
| RX 7900 XT | Qwen2.5-1.5B | 128 | 1,704 ms | 3.0 ms |
| RX 7900 XT | Qwen2.5-1.5B | 1,000 | 20,321 ms | 13.5 ms |

The restore starts from a blob already in memory. Its time covers parsing the blob, checking its digest, uploading
its pages and waiting for the upload. Reading the blob from storage is not included: the 1.5B blobs are 1.8 MB at
128 tokens and 14.3 MB at 1,000.

## Compatibility and required action

- The change is additive: no declaration, struct layout, status ordinal or sequence save format changes. The GPU
  verbs and their status were already exported, so a host that never called them sees no API difference. Cached
  `SPX1` blobs are another matter, as the next item says.
- **A blob is bound to the engine version that wrote it.** `SPX1` blobs written by 1.14.0 or 1.15.0, CPU or GPU, are
  refused by 1.16.0 with `SSLM_RESTORE_PRODUCER_MISMATCH`. The match is exact on major, minor and patch, so a
  later patch release will refuse 1.16.0's blobs too. A host that caches blobs across an engine upgrade must
  rebuild them by prefill. Key a cache by engine version, and on the GPU also by adapter vendor and device.
- Sequence saves (`SSB5`, `SSB6`, and the GPU's `SLM5` and `SLM6`) are unchanged.
- No model artifact needs reconversion, and the shaders are unchanged.

## Known issue

- RTX 50-series (Blackwell) GPUs fail parts of the GPU test suite; under investigation; use the CPU backend there.

## Verification

The test results are summarized in [`1.16.0-verification.md`](1.16.0-verification.md): the GPU save and restore
cells and the paged-KV GPU cells on the RTX 2080 SUPER and the RX 7900 XTX; the real-model cells, byte identity and
speed on the RTX 2080 SUPER and the RX 7900 XT; the cross-card refusal in both directions; reading 1.13.1's GPU
saves and refusing 1.14.0's blobs; and the release-tree checks.
