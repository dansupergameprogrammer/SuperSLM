# v1.3.1 -- the CI matrix, green, and the engine's geometry decoupled from the square case

A patch on 1.3.0. Six CI jobs behind 1.3.0's own guarantees are fixed at source, and the hosted
matrix is green for the first time since before the 1.3.0 tag. The engine's attention geometry no
longer requires `hidden_size == num_attention_heads * head_dim`, end to end through the LoRA
adapter path.

### What's fixed

- **The Linux/ELF FP-free scan leg now accepts `bswap`** (a pure integer byte-reversal, not
  floating-point arithmetic), closing the one real reject the leg's own hosted run reported.
- **`DynamicScaleReciprocal`'s reciprocal seed no longer has signed-integer-overflow undefined
  behaviour** at non-canonical magnitudes. No emitted bit moves — the UB is removed, not the
  arithmetic.
- **The census suite's own line-ending regression test now discriminates on every checkout
  convention**, not only the one this project happens to develop on.
- **`fp-free-scan-gate` no longer guesses which MSVC edition a Windows runner carries.** It
  resolves `VsDevCmd.bat` itself, using the runner's own `vswhere`, and is pinned to the
  `windows-2022` image its own red suite is commissioned against.
- **The coverage floors are re-measured against the sanctioned hosted cell**, closing coverage
  debt from unrelated feature work.
- **`tools/convert_tokenizer.py`'s checkpoint-path parsing is OS-independent** — a Windows-style
  checkpoint path no longer produces a wrong CONFIG model label when the converter runs on a
  POSIX host.

### The engine: non-square attention geometry

- **`CheckConfigGeometry` no longer requires a square `hidden_size == num_attention_heads *
  head_dim` identity.** `q_width` is now an independently derived, independently threaded
  quantity through the forward path and the LoRA adapter-marshal path alike. A checkpoint with
  `q_width != hidden_size` — previously a named load-time rejection — now converts and loads.

### Not in this release

- **The Qwen3-arch pin.** Ask 5's Tracks C and E (converter-side namespace/QK-norm detection,
  tokenizer schema support) are on `main` and ship in this tag's own code, because they are
  additive and tools-only — but the architecture pin itself is not claimed here. It lands as
  **1.4.0**, once Track B (the forward call site) is built. Do not build against 1.3.1 expecting
  a runnable Qwen3-Embedding candidate.
- **The Linux/ELF FP-free guarantee.** The leg is enforced and green in CI as of this patch, but
  the design's own must-reject population for that leg is still unbuilt. 1.3.0 promised delivery
  "for 1.3.1"; that promise is carried forward, not delivered here.
