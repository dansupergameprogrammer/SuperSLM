# SuperSLM 1.6.0

SuperSLM 1.6.0 expands schema-constrained generation on the CPU and D3D12 GPU paths, preserves
schema progress across sequence saves, adds explicit schema-state queries and GPU prefill-hidden
readback, and makes the public ABI ready for modular export/import builds.

## What changed

The schema compiler now supports an unbounded free-text `"type": "string"` field. The value is the
model's text up to its first unescaped quote; callers should prompt for plain text when an internal
quote is likely. The field has no engine-enforced length limit, so callers must use the bound and
accepting queries rather than a token-count guess to decide whether a budget-stopped value is
complete. Empty and punctuation-only values are not representable by this leaf.

Schema compilation now excludes tokenizer special and added-token ids structurally through the
required `special_ids` input. It accepts non-constraining JSON-Schema annotations, accepts `type`
alongside `enum` when the types agree, and refuses unsupported constraining keywords instead of
silently ignoring them. The byte-level vocabulary interface requires `Sequence[bytes]` and reports
a `TypeError` for text elements.

CPU callers can query whether a sequence has a schema bound with `sslm_seq_schema_bound`. GPU
callers gain the matching bound query and an exact accepting-state query. GPU queries are host-only
and do not submit device work. CPU and GPU dead ends now have matching deterministic behavior, and
reset is a symmetric restart operation from every valid idle/CPU state.

Schema bind, rebind, and unbind are valid only on a newly created or reset sequence. A generation
call that passes argument validation makes the sequence ineligible until reset,
including a valid no-op call or CPU empty-prefix adoption. A call rejected for invalid arguments
leaves the sequence untouched and still bindable; GPU Submitted/busy refusals likewise preserve
eligibility. Restored sequences must be reset before binding.

The GPU API adds `sslm_gpu_seq_read_prefill_final_hidden` and
`sslm_gpu_model_hidden_size`. A successful prompt or schema-content prefill records the post-final-
norm hidden state for readback; later embed/decode/finish calls do not replace that snapshot. Reset
or an admitted prefill failure invalidates it.

Every public C ABI verb and supported C++ engine declaration now carries the empty-by-default
`SUPERSLM_API` slot, allowing a shared-library build to define export/import behavior without
changing call sites. The installed GPU library no longer honors the two asynchronous UAV/SRV
rebind fault variables outside the dedicated fault-pin build.

## Compatibility and required action

GPU sequence saves now use `SLM5`, adding schema binding, parser walk state, and ready-for-logits
state. SuperSLM 1.6.0 continues to restore older `SLM4` saves, defaulting their schema binding to
unbound. SuperSLM 1.5.0 cannot restore a new `SLM5` save.

After restore, reset the sequence before binding, rebinding, or unbinding a schema. After any
generation call that passes argument validation, reset before changing the binding. A call rejected
for invalid arguments does not require that reset because it leaves the sequence untouched and
still bindable.

No model-artifact reconversion is required solely for the runtime changes in this release. Schema
artifacts should be regenerated when adopting the new compiler behavior, especially structural
special-token exclusion or unbounded free-text fields.

## Measured evidence

The 1.6.0 release gate covers CPU/GPU schema lifecycle parity, save/restore, deterministic dead-end
reproduction, reset/reuse, prefix adoption, query state, compiler acceptance/refusal, and the real
GPU model path. The registered real-model run reaches its 300-token budget with matching CPU/GPU
accepting state and nonzero GPU submit, dispatch, wait, and ready counters.
